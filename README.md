# NetPractice

## Description

NetPractice is a hands-on networking project from the 42 curriculum. Its goal is to learn how small networks are configured by fixing broken ones. Using a web-based training interface, I completed 10 progressively harder levels by assigning correct IP addresses, subnet masks, routes and default gateways so that every host in each network can communicate as required.

Each level presents a topology (hosts, switches, routers and the internet) with missing or invalid configuration. The task is to analyse the diagram and choose values so that:

- Every machine on the same local network shares the same network address and has a unique host address.
- Hosts reach other networks through the right gateway.
- Routers have a correct interface in each network they connect, and a correct routing table.
- Traffic to the internet goes through the proper default route.

Skills practised: reading network diagrams, subnetting, and diagnosing why two machines can or cannot talk to each other.

## Instructions

### Running the training interface

1. Go to the netpractice directory.
2. Start it with the provided script:
   ```bash
   ./run.sh
   ```
   If the script is not executable, run `chmod +x run.sh` first.
3. Open the address printed in the terminal (or the interface page provided with the subject) in a web browser.
4. Select a level, fill in the editable fields (IP addresses, subnet masks, routing table entries) and use the interface's check function to validate the configuration.

### Exporting configurations

Once a level is solved and validated:

1. Use the interface's **export** option to save the level's configuration to a file.
2. Repeat for each of the 10 levels.
3. Keep the exported files unmodified so they can be loaded and checked during evaluation.

### Submission requirements

- The 10 exported configuration files (one per level) are placed at the root of the repository, together with this `README.md`.
- Only the work present in the Git repository is evaluated, so everything must be committed and pushed before the deadline.

```
.
├── README.md
├── level1.json   (exported configuration)
├── level2.json
├── ...
└── level10.json
```

The exact file names and extensions are those generated by the interface's export function.

## Resources

### Networking concepts studied

- **TCP/IP addressing**: IPv4 addresses, network part vs host part, unique addressing inside a network.
- **Subnet masks**: dotted-decimal and CIDR notation (e.g. `/24`); computing the network address, broadcast address and usable host range.
- **Default gateways**: the router address a host uses to reach networks outside its own.
- **Routers**: connecting several networks, one interface per network, routing tables and default routes.
- **Switches**: connecting hosts inside one local network (layer 2) without changing addressing.
- **OSI model**: the seven layers, with a focus on layer 2 (switching), layer 3 (IP and routing) and layer 4 (TCP/UDP).
- **Public vs private addressing**: RFC 1918 ranges, and why private addresses are not routable on the internet.
- **Special addresses**: loopback (`127.0.0.0/8`), network and broadcast addresses, which cannot be assigned to hosts.
